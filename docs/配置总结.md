# 配置总结

本文档汇总与代理（proxy）及连接相关的配置项、存储位置和界面入口。

---

## 一、配置项一览

### 1. 代理连接信息（用于连接 / 启动时传参）

| 配置项 | 说明 | 默认值 | 存储 Key | 界面位置 |
|--------|------|--------|----------|----------|
| **IP** | 代理监听地址，本机一般为 127.0.0.1 | 127.0.0.1 | `proxy_connect_ip` | 代理配置页 · 代理连接信息卡片 |
| **端口** | 代理 HTTP/WS 端口 | 8443 | `proxy_connect_port` | 同上 |
| **PIN** | 6 位配对码，可选；填写后启动代理可自动配对并连接 | — | `proxy_connect_pin` | 同上 |

- **有保存连接时**：页面只读展示当前连接的 IP / 端口 / PIN；启动代理会用该连接信息并启动后自动连接。
- **无保存连接时**：可编辑 IP、端口、PIN；若填 6 位 PIN 再点「启动代理」，会带 `-pin` 启动并在启动后自动配对、连接；同时会写入上述 Key 作为下次默认。

### 2. 代理程序与启动参数

| 配置项 | 说明 | 默认/行为 | 存储 Key | 界面位置 |
|--------|------|------------|----------|----------|
| **代理程序路径** | 可执行文件路径 | 留空时：Debug 优先用项目内 `proxy/xassistant-proxy`，否则用 .app 内 `xassistant-proxy` | `proxy_executable_path` | 代理配置页 · 代理程序路径输入框 |
| **OpenClaw** | 是否启用 OpenClaw | 关 | 见下 JSON | 代理配置页 · 代理启动参数（展开） |
| **OpenClaw Token** | OpenClaw 令牌 | 空 | 同上 | 同上 |
| **OpenClaw URL** | OpenClaw 服务地址 | 空 | 同上 | 同上 |
| **允许本地无鉴权** | `-allow-local-no-auth` | 关 | 同上 | 同上 |
| **技能路径** | `-skills-path`，技能目录 | 空 | 同上 | 同上 · 技能路径 + 选择目录 |
| **工作目录** | `-workdir`，proxy 工作目录 | 空 | 同上 | 同上 · 工作目录 + 选择目录 |
| **日志文件路径** | `-log`，代理日志文件 | 留空时用 `~/Library/Logs/xassistant-proxy/proxy.log` | 同上 | 同上 · 日志文件路径 + 选择/查看日志 |

上述启动参数整体以 JSON 存于 **`proxy_launch_config`**，对应 `ProxyLaunchConfig`（见 `lib/services/proxy_launch_service.dart`）。

### 3. 连接信息（配对后保存）

| 数据 | 说明 | 存储 Key |
|------|------|----------|
| 连接信息 | 配对成功后保存的 IP、端口、token、deviceName、pairedAt、pin | `connection_info`（ConnectionService） |

用于：API 请求（含技能路径等）、WebSocket 连接、代理存活检测。  
清除或重新配对会更新/清空该存储。

---

## 二、界面入口与流程

### 代理配置页（主要配置入口）

- **入口**：底部栏「设置」→ 在 macOS 且代理未运行时自动显示代理配置；或从系统设置内进入代理配置。
- **路由**：`/proxy-config`（单独页）、`/config`（设置 Tab，根据状态切代理配置 / 系统设置）。
- **能力**：
  - 展示/编辑 **代理连接信息**（IP、端口、PIN）。
  - 展示 **代理状态**（已运行 / 未运行），支持「检测」；无连接时可用当前表单的 IP/端口做检测。
  - 配置 **代理程序路径** 与 **代理启动参数**（含技能路径、工作目录、日志路径等）。
  - **启动代理**：有连接时用保存连接信息启动并自动连接；无连接时若填 6 位 PIN 则带 PIN 启动并自动配对连接；启动后会做自动检测并刷新技能配置。
  - **关闭代理**：通过 `/api/shutdown` 关闭，并刷新状态。
  - **进入应用**：返回主功能界面。

### 系统设置页

- 可进入「代理配置」、管理 **技能路径**（通过 proxy API 的 `/api/config/skill-paths` 读写）。
- 技能路径等依赖「当前连接」；重启代理并重新连接后会自动刷新技能相关 Provider（`skillsProvider`、`skillPathsProvider`）。

---

## 三、存储与 Provider 对应关系

| 存储 / 数据源 | 用途 |
|----------------|------|
| SharedPreferences：`proxy_executable_path`、`proxy_launch_config`、`proxy_connect_ip/port/pin` | 代理路径、启动参数、连接默认值 |
| SharedPreferences：`connection_info` | 配对后的连接（API/WS/检测） |
| `proxyStatusProvider` | 代理是否运行（idle / checking / running / notRunning），可带 ip/port 检测 |
| `savedConnectionProvider` | 当前保存的连接，供 SkillApiService、检测等使用 |
| `skillsProvider` / `skillPathsProvider` | 技能列表、技能路径；连接成功后或重启代理并连接后会刷新 |

---

## 四、启动命令与刷新逻辑简述

- **启动命令**：由 `ProxyLaunchService.startProxy` / `buildLaunchCommandString` 根据「代理程序路径 + 连接信息（端口、PIN）+ ProxyLaunchConfig」拼出，例如：
  - `-port`、`-host 0.0.0.0`、可选 `-pin`、`-openclaw`、`-openclaw-token`、`-openclaw-url`、`-allow-local-no-auth`、`-skills-path`、`-workdir`、`-log`。
- **启动后**：有连接则自动连接并刷新 `savedConnectionProvider`、`skillsProvider`、`skillPathsProvider`；无连接但填了 PIN 则自动配对、连接并同样刷新技能相关配置；关闭代理后会 await 一次检测，保证状态刷新。

以上为当前「配置」相关逻辑的总结，便于排查和扩展。
